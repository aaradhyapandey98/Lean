# Instructions for contributors and future sessions

## Scope and source fidelity

The source target is arXiv:2605.16645v1. Identify statements by section and equation as well as printed number: some source numbers repeat. Preserve direction of inequalities, order of distributions, test measurability, parameter domains, nondegeneracy conditions, and ambient distribution-family restrictions.

Read `docs/PAPER_AUDIT.md`, `docs/INDEPENDENT_REVIEW.md`, and `docs/STATEMENT_REVIEW.md` before extending the library. A source issue must remain visible. A corrected theorem must be labeled as corrected and explain its relationship to the printed statement. Do not silently strengthen hypotheses or formalize a false statement.

## Proof integrity

- No `sorry`, `admit`, new `axiom`, `unsafe`, or native computation shortcut in project Lean sources.
- Do not hide target conclusions in hypotheses, typeclasses, structures, opaque definitions, or equivalences.
- Minimize assumptions theorem by theorem. Prefer existing mathlib results with explicit source correspondence.
- Every new declaration must be included in `declarations.json`, and every library module must be imported by the library root.
- Run `lake build`, structural checks, and `#print axioms` auditing. A source scan alone never establishes verification.
- Keep axiom evidence bound to the exact Lean files, lake configuration, toolchain and dependency lockfile. An evidence mismatch must make the website fail closed to unverified.
- Distinguish kernel checking from independent statement review. Neither substitutes for the other.
- Keep unfinished target statements in documentation/catalog metadata, outside the checked Lean library. No assumed statistical theorems in the trusted import path.

## Collaboration

Give agents small, disjoint tasks with exact source anchors and explicit output files. Use independent review for theorem statements and material mathematical changes. Do not allow multiple workers to edit a shared file concurrently. Integrate and compile before reporting completion.

## Continuity

At the end of substantive work, update `docs/SESSION_HANDOFF.md` with the exact revision, build commands/results, completed declarations, unresolved issues and next obligations. Do not claim completion of the whole paper until every advertised target has checked code and a statement-fidelity review.

## Website

`catalog.json` is the human-authored mathematical map. `site/data/proofs.js` is generated by `scripts/build_site.py` from actual Lean source and optional matching audit evidence. Do not hand-author a checked badge. Pending entries have no fake Lean proof. Keep proof-code content safely text-rendered and usable without remote scripts.
